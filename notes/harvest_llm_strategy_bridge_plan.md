# Harvest LLM Strategy Bridge Plan

## Purpose

The LLM bridge should test whether the Stage A oversight findings carry over when some strategies are generated by language models. It should not use live LLM agents as the next step.

The reason is control. Stage A already uses structured Harvest strategies, mutation, and search-generated entrants. An LLM bridge should preserve that structure by asking a model to generate complete strategy specifications that can be inspected and evaluated. This keeps the experiment reproducible and avoids turning the project into a prompt or model leaderboard.

## What An LLM Strategy Bank Means

An LLM strategy bank is a fixed collection of valid Harvest strategy specifications generated by a language model.

Each generated strategy should use the same strategy structure as the current Harvest experiments. That means the model generates parameter values for an inspectable strategy rather than free-form code or live actions. The strategy can then be validated, clamped to allowed ranges, deduplicated, and sampled into a population.

The bank should be saved and reused. Once a bank is generated, the same strategies can be evaluated under no oversight, local oversight, global signal, and hybrid oversight.

## Accepted Strategy Format

The accepted format should match the existing Harvest strategy representation. A generated strategy should specify:

- patch thresholds for low and high local resource levels;
- harvest fractions for low, medium, and high resource states;
- announced restraint behavior;
- credit request behavior;
- credit offer behavior;
- neighbor reciprocity behavior;
- credit response behavior;
- compliance margin under a governance cap.

The model may include a short rationale field for inspection, but the rationale must not affect execution. Deduplication should ignore free-text rationale and compare the executable strategy fields.

## First Pilot Scope

The first LLM bridge should be deliberately narrow.

Use one or two models, depending on access. A local model is sufficient for the first smoke test. A stronger API model is useful if access is available, but the pilot should not depend on it.

Use two prompt attitudes: cooperative and exploitative. The purpose is to see whether model-generated strategy families differ enough to affect the oversight evaluation.

Use one fixed prompt template. Do not run prompt-style comparisons in the first pilot.

Target a small accepted bank first, such as 32 valid unique strategies per model-attitude pair. Increase to 128 only if validity and diversity are stable.

## First Evaluation

The first evaluation should reuse the Stage A pipeline rather than creating a new environment.

Run a small governance map with:

- stress settings: moderate-coupling and high-coupling commons;
- conditions: no oversight, local oversight, global signal, and hybrid oversight;
- strategy mix: cooperative-heavy, balanced, and exploitative-heavy;
- overseer capability: strong and limited;
- actor capability label: model-generated.

The main comparison is whether oversight rankings remain similar when strategies come from model-generated banks instead of hand-designed and search-generated entrants.

## Success Criteria

The bridge is usable if:

- the model produces valid structured strategies at a high enough rate;
- generated strategies are not all duplicates;
- cooperative and exploitative prompt attitudes produce measurably different behavior;
- exploitative-heavy populations worsen at least one safety or resource metric under no oversight;
- the existing Stage A summary pipeline can process the model-generated runs without special manual cleanup.

The bridge is paper-useful if:

- local, global-signal, and hybrid oversight remain empirically distinguishable;
- the result either supports or challenges the Stage A architecture ranking;
- the analysis can be explained as a strategy-source robustness test, not as a live LLM-agent benchmark.

## Deferred Work

Live LLM agents should remain deferred. They can be considered after the structured strategy-bank module works.

Direct actor-overseer capability mismatch should also remain a later step. Stage A varies capability through search and oversight limits. The LLM bridge varies the source of strategies. A later task can vary actor and overseer capability more directly through planning depth, tool access, information access, and inspection budget.
